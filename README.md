## 🚨 Motivation — The Problem Nobody Wants to Talk About

Modern Vision-Language Models (VLMs) are genuinely impressive. Give them an MRI and they produce fluent, confident-sounding radiology reports. The problem is that "fluent and confident" does not mean "correct."

These models are **System 1 thinkers** — they pattern-match from pixels to text in one shot. There is no reasoning step, no checking, no constraint. If the model has seen enough reports that mention "necrosis," it will sometimes mention necrosis even when there is none. If the training distribution had more left-lobe tumors, it will bias toward the left lobe. This is the **clinical hallucination problem**, and it is a serious barrier to deploying AI in radiology.

We define this as the **Trust Gap**:

> *A radiologist cannot trust a model that cannot explain why it said what it said.*

The standard fix — fine-tuning on more data — does not solve this. It just shifts where the hallucinations happen.

---

## 🏗️ Our Approach — The Architecture

Instead of going end-to-end (Image → VLM → Report), we insert a deterministic intermediary: a **Knowledge Graph (KG) Payload**.

```
MRI Scan
    ↓
[Segmentation Model]  ←── generates predicted masks
    ↓
[Feature Extraction]  ←── volume, lobe, diameter, grade, laterality
    ↓
[Knowledge Graph / JSON Payload]  ←── structured, deterministic, auditable
    ↓
[LLM (Text-Only)]  ←── grounded generation with KG as factual guardrail
    ↓
Radiology Report
```

The KG payload is a structured JSON object that encodes **exactly** what the segmentation mask says — nothing more, nothing less. The LLM's job is no longer to infer clinical facts from pixels. It is to **translate a structured clinical fact-sheet into fluent prose**, which is a much easier and safer task.

This is why we call it **Neuro-Symbolic**: the neural component (segmentation + LLM) handles perception and language, while the symbolic component (KG, schema, taxonomy) handles knowledge representation and factual grounding.

### Why Does This Work?

| Property | End-to-End VLMs | Our Architecture |
|---|---|---|
| Hallucination Source | Anywhere in the pipeline | Bounded to segmentation error only |
| Auditability | ❌ Black box | ✅ KG payload is human-readable |
| Clinical Fact Fidelity | Probabilistic | Deterministic (if KG is correct) |
| Robustness to Noise | Unknown | Measurable via Payload Consistency |
| Trust Gap | Unaddressed | Structurally mitigated |

## 🔬 Experimental Setup

We ran **18 permutations** across two dimensions: mask quality and model type.

### Mask Conditions

| Condition | Description |
|---|---|
| **True Masks** | Perfect ground-truth segmentations — ideal scenario |
| **Predicted Masks** | Noisy masks generated by our segmentation model — real-world scenario |

Running both conditions lets us measure **clinical robustness**: does the model degrade when upstream segmentation is imperfect? Because in deployment, it always will be.

### Baseline Models (End-to-End VLMs)

These take the raw MRI as input and generate a report directly.

| Model | Size | Type |
|---|---|---|
| **LLaVA** | 13B | General-purpose VLM |
| **MedGemma** | 27B | Medical-domain VLM |
| **Qwen-VL** | 7B | General-purpose VLM |

### Proposed Models (Neuro-Symbolic, KG-Grounded)

These take the KG JSON payload as input and generate a report from structured facts.

| Model | Size | Notes |
|---|---|---|
| **Llama 3** | 8B | Strong instruction follower |
| **DeepSeek-R1** | 13B | Reasoning-augmented, our SOTA pick |
| **Meditron-v3** | 7B | Medical-domain fine-tuned |

### Ablation

All three proposed models were evaluated **with** and **without** the KG payload, to isolate the actual contribution of the knowledge graph.

## 📊 Evaluation Metrics

We deliberately avoided BLEU and ROUGE. These metrics reward lexical overlap and have been shown to correlate poorly with clinical correctness. A report that says "no mass lesion identified" scores terribly against a ground truth that says "absence of tumor" — even though they mean the same thing.

Instead, we used three metrics:

### 1. GREEN Score (Generative Radiology Evaluation & Error Notation)

- An **LLM-as-a-judge** metric designed specifically for radiology
- It penalizes **clinically significant errors** — wrong side, wrong lobe, wrong grade, wrong finding
- Outputs both a score and a **Hallucination Rate** (percentage of statements not grounded in the reference)
- Unlike BLEU, it understands clinical paraphrases and focuses on what matters

### 2. Payload Consistency Score *(Our Custom Metric)*

- We built this ourselves to measure **Data-to-Text Fidelity**
- For each generated report, it checks what percentage of the KG variables (Volume, Lobe, Diameter, Grade, Laterality) actually made it into the prose
- Formula: `Payload Consistency = (KG fields present in report) / (total KG fields) × 100`
- This is **fully deterministic** — no LLM judge, no ambiguity
- A model that ignores the payload and hallucinates will score low here even if the prose sounds good

### 3. RadGraph Proxy

- Measures **factual entity overlap** between generated and reference reports
- Parses clinical entities (findings, anatomy, attributes) and compares them structurally
- Complements GREEN by catching entity-level errors that sentence-level scoring might miss

## 📈 Results & Key Findings

### Top-Level Numbers

| Metric | Baseline VLMs (avg.) | Proposed Architecture (best) | Change |
|---|---|---|---|
| GREEN Score | — | — | **+162.73%** ⬆️ |
| Hallucination Rate | — | — | **−69.48%** ⬇️ |

These numbers are not marginal improvements. A 162% jump in GREEN score means the proposed architecture is producing reports that are categorically more clinically accurate — not just slightly better phrasing.

---

### Finding 1: The KG Payload Is Doing Real Work

The ablation (with vs. without KG) confirmed that the payload is not decorative. Removing it caused consistent drops in both GREEN and Payload Consistency across all three proposed models. The LLM on its own is not the fix — the structured factual grounding is.

---

### Finding 2: Generalist vs. Specialist — The Unexpected Result

This is probably the most interesting finding in the project.

**Llama 3** achieved the highest Payload Consistency score on True Masks. It is an almost perfect instruction follower — it reads the JSON, extracts the facts, and writes them into the report with high fidelity.

**DeepSeek-R1 (13B)** was our final SOTA pick, and not because it beat Llama 3 on raw consistency. It didn't, under perfect conditions. The reason DeepSeek-R1 wins is **robustness under noise**.

When we switched from True Masks to Predicted Masks (the realistic, noisy condition), Llama 3's consistency dropped. DeepSeek-R1's did not degrade nearly as much. It maintained high clinical accuracy even when the upstream segmentation was imperfect.

```
True Masks → Predicted Masks:
  Llama 3:      Payload Consistency ↓ significantly
  DeepSeek-R1:  Payload Consistency ≈ stable ✅
```

In real-world deployment, you will never have perfect segmentation. This makes DeepSeek-R1 the only viable candidate for production. Its reasoning capability (the "R1" in the name) seems to help it handle ambiguous or incomplete KG payloads more gracefully.

> **The lesson:** Optimizing for performance under ideal conditions is not the same as optimizing for real-world reliability. For medical AI, robustness to upstream noise is arguably more important than peak performance.

## ▶️ How to Run

### 1. Set Up Model Servers

Open `vlm_server.ipynb` and start the Ollama/vLLM endpoint for whichever models you want to run. The notebook handles model loading and server configuration.

### 2. Run the Baseline

Open `baseline_pipeline.ipynb`. This will:
- Load MRI scans
- Pass them directly to the VLM endpoints
- Generate and save reports to `outputs/`

### 3. Run the Proposed Pipeline

Open `proposed_pipeline.ipynb`. This will:
- Load segmentation masks (true or predicted, configurable)
- Extract clinical features → build KG JSON payload
- Pass payload to the LLM endpoint
- Generate and save grounded reports to `outputs/`

### 4. Evaluate Everything

Open `evaluation.ipynb`. This runs all three metrics (GREEN, Payload Consistency, RadGraph) across all saved reports and generates comparison plots. All results are saved to `outputs/`.

## 💬 Discussion & Takeaways

A few things worth saying explicitly:

**This is not just an engineering project.** The core contribution is a methodological argument: that factual grounding through symbolic intermediaries is a more principled approach to high-stakes text generation than scaling up probabilistic end-to-end models. The results support this argument strongly.

**The metrics matter.** Using BLEU/ROUGE would have buried the real signal. Payload Consistency, which we defined ourselves, turned out to be one of the most discriminative metrics in the study — it directly measures whether the model is actually using the information it was given.

**DeepSeek-R1's robustness is the real story.** The +162% headline number is impressive, but the True→Predicted degradation analysis is what would actually matter to a clinician evaluating this for deployment. A model that fails gracefully is more trustworthy than a model that peaks under ideal conditions.

**Limitations:** The evaluation is on a fixed dataset. Clinical generalization would require broader validation. The KG schema is also domain-specific (neuro-oncology) and would need extension for other modalities.
